# EduPulse SMT School Send Package

## Purpose

This is the master send guide for school-facing rollout materials. Use it to decide what to send, in what order, and whether to send a template or a filled sample.

## Recommended Default Package

For a normal school onboarding or sales-to-implementation handoff, send these in this order:

1. `SCHOOL_WELCOME_EMAIL_TEMPLATE.md`
2. `SCHOOL_CLIENT_LAUNCH_PACKET.md`
3. `SCHOOL_IMPLEMENTATION_GUIDE.md`
4. `SCHOOL_WELCOME_PACK.md`

If you need a shorter version, send only:

1. `ONBOARDING_EMAIL_TEMPLATE.md`
2. `SCHOOL_CLIENT_LAUNCH_PACKET.md`

## Demo-Ready Sample Package

For demos, presentations, investor previews, or internal rehearsals, use the filled sample versions:

1. `SCHOOL_WELCOME_EMAIL_TEMPLATE_SAMPLE.md`
2. `SCHOOL_CLIENT_LAUNCH_PACKET_SAMPLE.md`
3. `SCHOOL_IMPLEMENTATION_GUIDE_SAMPLE.md`
4. `SCHOOL_WELCOME_PACK_SAMPLE.md`
5. `ONBOARDING_EMAIL_TEMPLATE_SAMPLE.md`

## When To Send Each Document

- `SCHOOL_WELCOME_EMAIL_TEMPLATE.md`
  Use as the primary kickoff email once a school is ready for onboarding.
- `ONBOARDING_EMAIL_TEMPLATE.md`
  Use when you want a lighter first contact that asks for onboarding inputs.
- `SCHOOL_CLIENT_LAUNCH_PACKET.md`
  Use as the main polished overview document for school leadership.
- `SCHOOL_IMPLEMENTATION_GUIDE.md`
  Use when the school wants more operational detail about rollout phases and responsibilities.
- `SCHOOL_WELCOME_PACK.md`
  Use as the shorter school-facing starter document.

## Pre-Send Checklist

Before sending any template externally:

1. Replace all placeholders with real school values.
2. Confirm the school name, code, plan, and go-live target date.
3. Confirm the school-side owner and billing contact details.
4. Confirm Daniel Asare Anyinam is still the correct visible owner and support contact.
5. Remove sections that do not apply to the school.
6. Convert to PDF if the school prefers attachment-based onboarding.

## Package Assembly Rules

- Do not send both the short and full email templates in the same thread unless there is a clear reason.
- Do not send both template and sample versions to a school; samples are for internal use, demos, and presentation contexts.
- Keep the launch packet as the main source of truth if multiple school-facing files are attached.
- If the school is already in active onboarding, prefer the welcome email plus launch packet over the shorter onboarding email.

## Internal Recommendation

For most real school launches, start with:

1. `SCHOOL_WELCOME_EMAIL_TEMPLATE.md`
2. `SCHOOL_CLIENT_LAUNCH_PACKET.md`

Then send the implementation guide only if the school asks for more detail or the rollout is operationally complex.

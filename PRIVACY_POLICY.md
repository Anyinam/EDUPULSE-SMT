## 7. DATA SHARING AND DISCLOSURE

### 7.1 Within the School

**Multi-Tenant Isolation:** EduPulse operates on a strict multi-tenant model. Each school's data is completely isolated from other schools. Data is only accessible to authorized users within the same school:

- **Proprietors:** Full access to all school data
- **Headmasters:** Access to academic and administrative data
- **Teachers:** Access to assigned classes and subjects
- **Finance Officers:** Access to financial records

### 7.2 Third-Party Service Providers

We share data with the following third-party processors under strict Data Processing Agreements:

1. **Paystack (Payment Processing)**
   - **Data Shared:** School name, email, subscription amount, payment metadata
   - **Purpose:** Processing subscription payments
   - **Location:** Nigeria (covered by ECOWAS data transfer framework)
   - **Privacy Policy:** https://paystack.com/privacy

2. **Meta (WhatsApp Business API)**
   - **Data Shared:** Parent phone numbers, message content (report cards, alerts)

   - **Purpose:** Sending transactional emails

   - **Privacy Policy:** https://policies.google.com/privacy

## 10. DATA SECURITY MEASURES

### 10.1 Technical Safeguards

1. **Encryption:**
   - **Data in Transit:** TLS 1.3 encryption for all communications
   - **Data at Rest:** AES-256 encryption for sensitive fields (email, phone numbers)
   - **Password Storage:** Bcrypt hashing with salt

2. **Access Controls:**
   - **Multi-Factor Authentication (MFA):** Available for all users
   - **Role-Based Access Control (RBAC):** Granular permissions based on user roles
   - **Session Management:** Automatic logout after inactivity
   - **IP Whitelisting:** Optional for school administrators

3. **Network Security:**
   - **Firewall:** UFW (Uncomplicated Firewall) blocking unauthorized ports
   - **DDoS Protection:** Cloudflare protection against distributed denial-of-service attacks
   - **Rate Limiting:** API rate limits to prevent abuse
   - **Web Application Firewall (WAF):** Protecting against common web vulnerabilities

4. **Database Security:**
   - **Connection Security:** SSL-encrypted database connections
   - **Access Restrictions:** Database accessible only from application servers
   - **Query Parameterization:** Protection against SQL injection
   - **Audit Logging:** All database modifications logged

5. **Financial Ledger Security:**
   - **HMAC-SHA256 Chaining:** Cryptographically signed ledger entries for immutability
   - **Verification System:** Real-time integrity checking of financial records
   - **Secret Key Management:** Ledger keys stored in secure environment variables

### 10.2 Organizational Safeguards

1. **Staff Training:**
   - All employees receive data protection training annually
   - Security awareness programs for phishing and social engineering
   - Incident response drills conducted quarterly

2. **Access Management:**
   - **Principle of Least Privilege:** Staff only access data necessary for their role
   - **Background Checks:** Staff handling sensitive data undergo background verification
   - **Confidentiality Agreements:** All staff sign NDAs and data protection agreements

3. **Vendor Management:**
   - **Due Diligence:** Security assessment of all third-party processors
   - **Data Processing Agreements:** Contractual obligations for data protection
   - **Regular Audits:** Annual security audits of critical vendors

4. **Incident Response:**
   - **24/7 Monitoring:** Sentry error tracking and UptimeRobot monitoring
   - **Incident Response Plan:** Documented procedures for data breaches
   - **Breach Notification:** Commitment to notify DPC and affected parties within 72 hours

### 10.3 Physical Security

- **Secure Data Centers:** Cloud infrastructure hosted in ISO 27001 certified facilities
- **Redundancy:** Backup systems in geographically separate locations
- **Environmental Controls:** Fire suppression, temperature control, power backups

### 10.4 Backup and Disaster Recovery

- **Daily Backups:** Automated database backups at 2:00 AM GMT daily
- **Retention:** Backups retained for 30 days
- **Encryption:** All backups encrypted with AES-256
- **Testing:** Backup restoration tested monthly
- **Disaster Recovery Plan:** RTO (Recovery Time Objective) of 4 hours, RPO (Recovery Point Objective) of 24 hours

## 19. GLOSSARY

**Data Controller:** The entity that determines the purposes and means of processing personal data (e.g., the school).

**Data Processor:** The entity that processes personal data on behalf of the data controller (e.g., EduPulse).

**Data Subject:** The individual to whom personal data relates (e.g., student, parent, staff member).

**Personal Data:** Any information relating to an identified or identifiable natural person.

**Processing:** Any operation performed on personal data (collection, storage, use, disclosure, deletion).

**Sensitive Personal Data:** Data revealing racial or ethnic origin, political opinions, religious or philosophical beliefs, trade union membership, health data, sex life, or criminal records.

**Multi-Tenant:** A software architecture where a single instance serves multiple customers (schools) with strict data isolation.

**HMAC-SHA256:** A cryptographic hash function used to ensure data integrity in financial ledgers.
